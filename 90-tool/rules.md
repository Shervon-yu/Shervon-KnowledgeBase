## 1. 总则

**一个会话 = 一本书 = `00-inbox` 下一个文件夹 = 一个入库夹。** 不并行、不批量、不跳步。文件夹缺失时按第 2 节自动建，不停下询问。
下文「入库夹」= 因一次入库而生成的那个文件夹，形如 `书名_作者_版次_年份`。

## 2. 输入

- `00-inbox` 顶层只认一个入库单元：**恰好一个文件夹 → 用它**；**只有散文件 → 自动建入库夹、把顶层散文件全部移入，继续，不询问**；**2 个以上文件夹 → 停，问处理哪一个**（不许自己挑）；**空 → 停，告诉用户放书**。
- 自动建夹的命名：取文件名里的书名与作者，缺项写 `NA`，形如 `书名_作者_NA_NA`；文件名带 `(作者编著)`/`（作者主编）` 的，去掉括号与「编著/主编/著/编」；书名内全角 `－` 归一为半角 `-`。**这只是初值**：解析完必须用正文版权页/CIP 校准书名、版次、年份（例：文件名「汽液」而版权页是「气液」），不符就改名——入库夹、md 文件名、`10-source` 目录、frontmatter 的 `title/src` 同步改，改完重跑 `catalog.ps1`。
- 文件夹名：`书名_作者_版次_年份`，缺项写 `NA`，例：`机械设计手册_成大先_第5版_2008`。
- 一个文件夹内可有多个文件（分册、扫描页、补充图），按文件名排序依次解析，合并成一份正文。
- 支持：`.pdf .png .jpg .jpeg .webp .bmp .tif .tiff`（走 MinerU）、`.md .txt`、`.docx .pptx .xlsx`（直接读 OOXML，不需要 Office）、`.html`（粗提取）。
- **入库成功后，`00-inbox` 里这个文件夹若已空则删除**（原件此时已移进 `10-source`，inbox 只作传送带，不作仓库）。解析失败或走第 9 节手工回退时**保留原文件**，并在 `todo.md` 留痕。
- 不支持：`.doc .ppt .xls`（97-2003）——要求另存为新格式。

## 3. 输出

- 原件 → `10-source\<层级>\<入库夹>\`（移动，保持原文件名）
- 正文与其他文档 → `20-md\<层级>\<入库夹>\`（入库夹根：`<入库夹>.md`，将来也可能是 txt/csv 等）
- 图示 → `20-md\<层级>\<入库夹>\图片\`（**所有插图集中放 `图片\`**，文件名见第 5 节）
- 隔离 → `20-md\_quarantine\Q-<入库夹>.md`
- 索引 → `30-wiki\manifest.csv`、`catalog.md`、`todo.md`（由 `catalog.ps1` 重建）
- 新建物（脚本/日志/笔记/临时目录）→ `40-new\`，一律不许落到根目录或 `20-md`、`10-source` 里

`<层级>` 默认为空（即直接放 `20-md\<入库夹>`），只有第 4 节阈值触发时才出现分类夹；`10-source` 与 `20-md` 的层级必须完全镜像。

frontmatter 字段：

```
id / title / authors / edition / year / kind / topic / pages / ocr /
quality / sha256 / src / files / added / missing
```

`kind` 取值：`book spec paper project web other note`（`spec` = 标准/规范，避免与解析档位 `standard` 混淆）。`topic` 填分类夹名；扁平时填 `NA`；分组后手工补或由 `catalog.ps1` 回写。

## 4. 分层（v2.0 核心）

### 4.1 硬上限

任一文件夹的直接子项（子文件夹数）**不得超过 40 个**。超过即为违规，必须先分组再入库。

### 4.2 阈值

令 **N** = `20-md` 下现有的入库夹总数（不含 `_quarantine`，含已被分组的）。

| N | 规则 |
|:---|:---|
| N < 20 | **只许扁平**：`20-md` 下只有入库夹，不建任何分类夹 |
| 20 ≤ N ≤ 40 | **可选分组**：能一眼看出某一主题 **≥ 3 个**入库夹同类时，可建一个分类夹把它们移进去；看不出就继续扁平 |
| N > 40 | **必须分组**：直到层数 x 满足 `40^(x-1) < N ≤ 40^x`，且每个文件夹直接子项 ≤ 40 |

- 例：N=41 → 至少 1 层分类夹、`20-md` 下 ≤40 个子项；N=1601 → 至少 2 层。
- 允许**分类夹与入库夹同层混放**（例如 `20-md\机械\` 与 `20-md\化工原理_…\` 并列）。
- 「明显同类」指同一学科、同一项目或同一来源的成套资料，不是硬性分类学。

### 4.3 分类夹命名

- 用主题词：`机械`、`流体`、`仪表`、`公司项目`、`奇门遁甲`……中英文皆可，不带序号前缀。
- 已存在同名或同义分类夹就**复用它**，不许建 `机械2`、`mechanical` 两个并列夹。
- 分类夹名不写进 `taxonomy.md` 也可以建；`taxonomy.md` 只是**建议清单**，不再是白名单。

### 4.4 重排时机（每进一本就重排）

**每次新增一个入库夹时，先判定它归哪个分类夹，再决定放哪一层**，不要等到硬阈值才动。

1. 先看现有一级/各级分类夹里**已经装着什么入库夹**——判断依据是夹内实际内容，不是夹名。
2. 有一看就合适的 → 直接放进去（需要时先建该分类夹）。
3. 没有合适的，但存在若干个能凑成一类的入库夹 → 新建分类夹，**只把本次这一本放进去；别人的入库夹不动**（批量归并见 4.5）。
4. 夹名不再贴合内容时**允许改名**（`仪表` → `测量与控制`）；改名后必须重跑 `catalog.ps1`。
5. 每次重排后自检：任一文件夹直接子项 ≤ 40；`20-md` 与 `10-source` 层级完全镜像。

### 4.5 谁负责重排

- 外部 agent：只决定**自己这一本**应放哪一层（复用已有分类夹或按 4.2 新建一个），**不移动别人的入库夹**。
- 全局重排（把散落入库夹归并、拆超限夹）由 **DSH** 负责；外部 agent 建分类夹时可移动本次入库的夹，归并既有夹只有 DSH 能做；`catalog.ps1` 会在 `todo.md` 里报「层级体检」（当前 N、是否超限、建议动作）。
- 任何移动之后必须重跑 `catalog.ps1`，否则索引路径失效。

## 5. 图示规则（强制）

原文出现"图X.X 说明"（含"如图所示（图 3-1 …）"）时：

- **正文**：文字照常转换，图号与说明原样保留（`图3-1 结构示意图`），不改写法、不删图号。
- **图片**：由 MinerU 导出（`--format zip` 的 `images/`），脚本读 `middle_json.json` 定位图题，改名后放入入库夹的 `图片\` 子目录。
- **文件名**：`图1.1 问题描述.jpg` = 图号 + 一个空格 + 说明；图号归一为 `图X.Y`；说明超 60 字截断。
- **禁用字符**：`( ) [ ] { } * ? : " < > | / \ # %` 一律换成空格或下划线——括号/方括号会截断 markdown 的 `![](...)` 链接，是硬错误；图题里的引用号（`[31]`、`[31-33]`）在命名前先剥掉。
- **多子图**：`图3.1 结构示意图_a.jpg`、`_b`、`_c`（不用 `(a)`）。
- **无图号**：`未命名图1.jpg`、`未命名图2.jpg`……
- **md 链接**：`![](图片/图1.1 问题描述.jpg)`——带 `图片/` 前缀，不出现绝对路径；**目标写真实文件名，含空格照写，不加 `%20`**（`check-links.ps1` 按原文判：含 `%` 一律记 bad，即使解码后文件存在）。
- **同号重复**：第二次起加 `_2`、`_3`，再与子图后缀组合为 `_a_2`。

## 6. 命名

`书名_作者_版次_年份.ext`；正文 md 与入库夹同名。入库夹名与 md 名必须一致。

## 7. 质检（自动，`ingest.ps1` 内）

| 指标 | 阈值 | 处置 |
|---|---|---|
| 有效字符（去空白） | < 200 | `quarantine` → `20-md\_quarantine\Q-*.md` |
| 有效字符 | 200 ~ 2000 | `warn`，照常入库，记 `todo.md` |
| U+FFFD 占比 | > 2% | `quarantine` |
| 单个 md/txt | > 5 MiB | 记 `todo.md`，不拦 |
| PDF 解析失败 | — | 原件归档，正文记 `pending`，进 `todo.md` |
| 图题存在但 MinerU 未导出图 | — | `figures.py`/`check-links.ps1` 报缺图数 + 清单，进 `todo.md`（可选：按页重解析补齐） |

隔离不等于删除：原件照样进 `10-source`，md 进 `_quarantine`，`manifest.csv` 与 `todo.md` 都留痕。

## 8. 禁止（九条）

1. 不删任何文件（原件、md、图片）；例外三条：`figures.py --dedupe` 删**同字节副本**（第 11 节）；`00-inbox` 里已成功入库且已清空的文件夹（第 2 节）；`check-links.ps1` 只删**指向不存在文件的链接标记**，不删图。
2. 不改 `10-source` 里的文件内容。
3. 不覆盖已有 md。
4. 不移动、不改名别人已入库的入库夹（全局重排是 DSH 的活）。
5. 不联网（不上传、不下载模型）。
6. 不安装软件。
7. 不新增分类夹以外的目录层级；层数超出第 4 节公式即违规。
8. 不跳过 MinerU 解析直接手写正文（预览可跳过，解析不可跳过）。
9. 不直接写 DSH 检索索引（插件私有 JSON，只能由 DSH 写）。

## 9. 手工回退（执行者不能跑命令时）

`30-wiki` 分两块，写者不同，不得越界：

- **人写区**（只有 LLM 写）：五个子目录 `pages` / `sources` / `comparisons` / `howto` / `openq`，外加 `glossary.md`（唯一译名表）与 `log.md`（变更日志）。人只在 Obsidian 里读，改动靠 git 审计。

- 新增子目录前必须先改 `AGENTS.wiki.md` 第 0 节，不得擅自开新层级。

### 12.1 建页判据（v3.10 起，唯一判据）

- 页单位 = **一断言簇**：同一结论的断言合为一页（定义 + 公式/判据 + 参数 + 边界 + 出处）；不同结论各自成页。
- 建页前提 = **有用**：能解决一个具体工程问题；写不出使用场景的不建页。
- **粒度下限**（v3.18）：一章内含多个独立判据的**须各自成页**；一类校核、一个公式体系算一个独立判据。把整章压成一页即违反本条。
- **附录按内容分流**（v3.18）：载有公式、判据或参数取值的附录按断言簇正常建页——如 GB/T 150.3 附录 A 非圆形截面容器、E 低温容器、F 防低温脆断校核、G 夹套容器，150.4 附录 A 锻焊、B 套合、C 多层包扎、E 低温脆断容器制造附加要求；纯查表附录（许用应力表、高温性能表、牌号对照表）与文书表（提案表）不建页。
- 显式禁止：按书的目录/章节建页；预设「一本书多少页」再往里塞内容；为思考题、参考文献、符号说明、索引建页。
- 每页必带 `question`（一个疑问句，见 §13），全库唯一；重复即合并或改页。
- 页数不设上限，也不设「每书页数」目标。
- 主题总览页：每个工程主题 1 页，放 `pages\`，命名 `<主题>-总览`，只做导航与取舍、不写推导；该主题的知识点页链回它。
- 非知识条目（思考题/参考文献/符号说明/索引）不建页，在该书 `sources\` 页章节地图里标注「未建页」。

### 12.2 五目录职责（v3.15 起）

- `pages\`：知识页——书内知识的一切落地页：机理与定义、公式/判据、参数范围、适用边界；设备结构与型式、零件；测量与实验方法；设计步骤；放大与工程实例；主题总览。`type` 用 `concept` 或 `entity`，两者同目录。
- `sources\`：每本书 1 页章节地图，只导航、不复述知识。
- `comparisons\`：跨书/跨标准同一量的口径差异，至少两处出处，写清差异性质。
- `openq\`：缺口与矛盾——无来源、单来源存疑、两源冲突、OCR 待核。有来源可解的不进这里。
- `howto\`：**项目复盘**（用户 2026-11-19 定义）。当用户用库内知识解决了一个具体工程难题之后，把那次事件提炼成一页存入库中：问题是什么、约束条件有哪些、用到库里哪些页（逐条 `[[...]]`）、怎么选/怎么算、结论与事后验证、哪些环节知识不够用。目的不是复述知识，而是留下「知识 → 用法」的证据链，让下次同类问题能直接照做。

`howto\` 页的额外约束：

- 命名 `howto\<任务名>.md`（例：`howto\DN800 搅拌釜轴封选型.md`），`type: howto`。
- 必须链回所用知识页（入链 ≥2 规则同样适用），否则这次复盘就脱离知识网、下次检索不到。
- 只写「这次是怎么用知识解决问题的」，不抄书的操作步骤；书里的东西由 `pages\` 承担，复盘只引用。
- 由用户发起（用户说「这次怎么做的记一下」），LLM 不擅自建；LLM 在解题过程中发现「库内知识被组合使用」时可提议，经用户确认后再建。
- 复盘里暴露的知识缺口，同步在 `openq\` 记一条并互相链接。

## 13. 页面契约（frontmatter 与硬约束）

字段顺序固定，不得增删或调序：

```
---
type: concept
title: 搅拌功率-功率准数
question: 搅拌功率怎么计算？
aliases: [功率准数, Np]
domain: 搅拌与混合设备
status: draft
confidence: high
sources:
  - book: 搅拌与混合设备设计选用手册
    section: §1.4
    lines: "#L960-#L1064"
related: ["[[搅拌功率-永田进治关联式]]"]
supersedes: []
updated: 2026-11-16
---
```

- `type` 六选一：`concept` / `entity` / `source` / `comparison` / `howto` / `openq`；除 `concept`、`entity` 同放 `pages\` 外，其余必须与所在目录一致。
- `question` 必填：一个疑问句（以 `？` 或 `?` 结尾），全库唯一；空、非疑问句、重复都会被 `wiki-lint.ps1` 第 10 项判错。
- `status` 四选一：`draft` / `stable` / `superseded` / `open`。
- `confidence` 三选一：`high` / `medium` / `low`；`low` 需在正文首段说明为何低。
- 单页 ≤300 行；超了拆页，原页留「→ 已拆至 [[新页]]」。
- **例外**：`index.md` 与各书知识点索引 `index-<领域>.md` 不设行数上限（由脚本生成、按 type/领域分表，行数随入库量线性增长），lint 第 4 项不检查这两类文件。
- 每页入链 ≥2，否则合并或删除。
- 图引用必须附 ≥1 句文字转述；转述不出则走视觉模型并在 `log.md` 记一条。
- **表格与公式（v3.17）**：单元格内公式一律行内 `$...$` 包裹（块级 `$$...$$` 在表格里不渲染）；单元格内不得出现裸 `|`——绝对值/条件概率用 `\vert`，成对定界用 `\lvert x\rvert`，`\left|`/`\right|` 写成 `\left\vert`/`\right\vert`；不得用 `\begin{array}` 伪造合并单元格，合并语义改 HTML 表格 `rowspan`/`colspan` 或拆行拆列，重建不了在 `openq\` 记一条。
- 文件名 = `title` = 正名；禁用字符 `\ / : * ? " < > |`。
- `sources` 必须块状三行写法（`book:` / `section:` / `lines:`）；行内 `sources: [书名]` 会被 `wiki-lint.ps1` 判「无来源」。
- 新建 `.ps1` 脚本必须带 UTF-8 BOM（`EF BB BF`），否则 PowerShell 5.1 按 ANSI 读中文会报语法错。
- 含中文的脚本一律用 `write` 工具落盘，不要用 `Out-File`/here-string（PS 5.1 会写出乱码）。

## 14. 引用格式（书名 + 节号 + 行号双轨）

正文引用一律写成：`《书名》§节号（#L行号）`，例：

```
《搅拌与混合设备设计选用手册》§1.4（#L960-#L1064）
```

- 节号用书中真实章节号，不自行编号、不猜。
- 行号指 `20-md\<入库夹>\<入库夹>.md` 的绝对行号。
- 行号随重解析漂移：md 重建后须按 §14 重算引用行号。v3.4 起锚点统一为物理页序，若仅锚点号变化而正文行序不变，行号只会在首页 frontmatter 分隔行处整体平移（本次入库实测 +2），按锚点比对即可校正，不必全量重扫。
- 只写书名不写节号 = 无来源，按 `AGENTS.wiki.md` §2 处理（进 `openq`）。
- 同一断言跨书时逐条列全，不合并成一条。


报告写 `30-wiki\_lint.md`（生成物，不进版本库）。

**提交信息格式**：`wiki(ingest): <书名> touch=N`；`crystallize` 与 `lint` 分别用 `wiki(crystallize):` / `wiki(lint):` 前缀。

## 16. 解析产物 → 20-md：生成规范（v3.2）

一条命令（MinerU 解析产物已在 `40-new\parse\<入库夹名>\` 或 `%TEMP%\mk-full\<入库夹名>\`）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File "90-tool\scripts\ingest-build.ps1" -Book "<入库夹名>"
```

内部六步：`md-build.py write`（按页序重建）→ `fig-names.py apply`（无图题图定名）→ `md-build.py prune`（未引用图归档）→ `check-links.ps1`（图链自检）→ `md-build.py verify`（标题体检，v3.16）→ 验收表 8 行。

v3.3 起 `ingest.ps1` 收尾**自动**调用本脚本（md 尚无锚点时），并把 MinerU zip 复制到 `40-new\parse\<入库夹名>\` 永久保留；单独手跑仅用于重建（`-Force`）。

**七条硬性产出**（缺一条都不算入库完成）：

1. 逐页 `<!-- page: N -->`，N 一律用**物理页序** `page_idx+1`（v3.4 起不再用页脚印刷页码；前后置页会让印刷页码与物理页序错位，混用两套编号会出现「锚点数对得上、页号却缺一半」的假通过）。锚点数必须等于 PDF 页数，且 1..N 连续无缺。
2. `type=equation` 的 block → 独立公式 `$$ ... $$`；`equation_inline` → 行内 `$...$`。丢公式是最常见的静默错误。
3. `table_body` 的 HTML → pipe 表格（colspan 补空列、rowspan 后续行留空），表题/表注各占一行。
4. 图名四级：①有图号图题 → `图X-Y 说明.jpg`；②同页紧跟的无号文字 → 该文字作图名；③方形小图（长边 ≤200 且宽高差 ≤15%）→ `二维码-第NN页.jpg`；④都没有 → `图_第NN页_n.jpg` 并进 `openq\` 登记，**不得编造图号**。
5. write 时必须保留原 md 的 YAML frontmatter（`catalog.ps1` 靠它认书目）。
6. 目录页的 `paragraph_title` 一律输出为 `- 文本` 列表，禁止生成 `## 第三章 ...` 假章标题。
7. **标题体检（v3.16）**：生成后必须跑 `python 90-tool\scripts\md-build.py verify "<入库夹名>"`，输出 `TITLE-CHECK OK` 才算过。`FAIL` 的三类硬伤必须当场补标题后重跑，不得只靠肉眼翻 md：
   - **粗体假标题**：该是标题的行还停在 `**1 范围**`、`**第 1 部分:通用要求**`、`**附录A**` 形态。GB/T 150 就是这么整本 0 个真标题的。
   - **整族标题没生成**：目录里有 `第X章`/`附录X`/裸编号章，md 里同类一个都没有；或正文引用了「附录 A」而 md 里没有任何附录标题行（GB/T 150 丢了 18 个附录标题行，正文全悬空）。
   - **可比族内部缺失**（目录与 md 同类数量差 ≤30% 时才逐条比对并列出缺项；差得更远视为「目录与正文不同源」，打印「跳过族」不报警）。
   孤立 h3/h4（无上级）、章号跳号属软警告，默认只提示；`--strict` 才按失败处理（GB/T 150.2 实际缺第 3、4 章，跳号是书的问题，不该卡流程）。
8. **表格公式定界符（v3.17）**：表格单元格内的公式必须写成行内 `$...$`——MinerU 直出的 pipe 表格常整列丢定界符（2026-11-19 实测 20-md 9986 行表格里 1361 行是裸 LaTeX，Obsidian 里显示成反斜杠源码）；单元格内裸 `|` 改 `\vert`（`\left|`/`\right|` → `\left\vert`/`\right\vert`），否则被当作列分隔符切断列。该补丁目前是人工后处理、未脚本化，重解析重建 md 后必须重做；`\begin{array}` 伪造的合并单元格须对 PDF 原表重建，不得保留。

**守卫与代价**：

- md 已是生成版（锚点 ≥10 且无 `图_第NN页_`）时，`ingest-build.ps1` 默认跳过重建，避免把人工定好的图名打回页码名；确需重建加 `-Force`。
- 新书（`refs-remap.py` 的 `book_of()` 未收录）**一律不用 refs-remap**，按 §14 用「旧/新 md 逐行比对 + 逐条原文校验」手工重取行号，只改本书专用页。
- 重建会换掉全部行号（旧书）。步骤固定：`git checkout -- '30-wiki' kb-blueprint.md` → `refs-remap.py dry`（报告落 `%TEMP%`）→ 人工核 LCS<14 的条目 → `refs-remap.py apply`。**同一批文件重复 apply 会把新行号再当旧行号映射一次**，每次重试前必须先 `git checkout`。
- `md-build.py prune` 把 md 未引用的图片移到 `40-new\_acl\orphan-images\<入库夹名>\`（可回滚，不删）。

**提交守卫（v3.7）**：`git add -A` 之后、`git commit` 之前先跑 `powershell -File 90-tool\scripts\precommit-guard.ps1`；暂存区出现删除项即中止，确认是有意删除再加 `-AllowDelete`。动机：2026-11-18 一次 `git add -A` 把一整本试点书的删除（md+319 图+11 个 wiki 页）一并提交，靠 `git checkout <旧提交> -- <路径>` 才恢复。

**完成判据（v3.17）**：七条全过才算入库完成，缺一不许写成「已入库」——
1. `ingest-build.ps1` 验收表八行全过（含标题体检 `OK`）+ `SELFCHECK unresolved=0`；
2. `wiki-lint.ps1` 0 条（十项）；
3. **覆盖率门** `coverage.py -Book "<入库夹名>" --strict` 退出码 0（本书 md 的每个 `###` 小节都至少被 wiki 引用一次；未被覆盖的节必须当场成页，不能留到汇报里）；
4. 图索引：`python 90-tool\scripts\figure-index.py -Book "<入库夹名>"` 生成 `30-wiki\figures-<入库夹名>.md`，行数（表体）须等于 20-md 内 `](图片/...)` 链接数；`整页图-pNN_n`、`未命名图N` 类无题图在 sources 页声明「无题非缺图」，缺图另见 `40-new\figures-report-*.json`；
5. 每页 `question` 非空、疑问句、全库唯一（lint 第 10 项 0 条）；
6. 已 `git commit`；
7. 表格内无未包裹 LaTeX：逐行检查 `20-md\<入库夹>\<入库夹>.md`，凡 `|` 开头且含 `\` 命令的行必须含 `$`。

> 教训（v3.6）：v3.3~v3.5 的判据只到「lint 0 + commit」，于是入库可以交出一个 8 页的 wiki 就宣布完成——判据里没有「书的内容被覆盖」这一项，机器又不会自己发现。覆盖率门就是补这个洞：它把「读没读完」变成可计算的退出码。
